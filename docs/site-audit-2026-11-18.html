Fixed and verified

Each fix was checked on a fresh production build (next build + next start), not just by reading the code.

Dead end 12 adventures with no operators sent people to an empty list

On Triund, Mera Peak, Lobuche, Rudranath, Yulla Kanda, Everest Three Passes, rafting and the five bike/cycle trips, the booking card said "Contact for pricing" and the phone bar said "See operators", both leading to "No operators listed yet". Cards said "Price: On request" with nobody to ask. Now the card says No operators listed yet and the button is See similar adventures, which scrolls to the similar trips (checked: it lands on them). Listing cards say Operators coming soon.

BookingSidebarCard.tsx · MobileBookBar.tsx · AdventureCard.tsx

SEO Those 12 pages promised operators in Google

Titles read "Triund Trek 2026: Compare Operators & Prices" and descriptions "Book the Triund Trek with a local operator". Now: "Triund Trek 2026: Route, Season & Difficulty" and "Plan the Triund Trek: route, best season, difficulty and how fit you need to be." A test now fails if a page with no operators mentions operators or booking.

src/lib/seo.ts · tests/data.test.ts

Dead links X, YouTube and LinkedIn accounts don't exist

twitter.com/trailtotides, youtube.com/@trailtotides and linkedin.com/company/trailtotides all return "not found". They were in the footer, the contact page, every email and the site's structured data (sameAs, which tells Google these are your profiles). Removed everywhere; Instagram, which is real, stays.

Footer.tsx · ContactClient.tsx · layout.tsx · email.ts

Dead links 6 Trek The Himalayas booking links were 404s

Deoriatal–Chandrashila, Kuari Pass, Bajre Dara, Doodhpathri, Khopra Ridge and Satopanth pointed to pages THT has moved. Their site returns 404 pages with a 200 status and blocks scripts, so these were checked in a real browser against THT's own sitemap. All 51 THT links now open the right trek page.

src/lib/data.ts

Dead links Suunto and COROS app links in the offline-maps guide

Both returned 404. Now app.suunto.com and coros.com/getapp (both checked, 200).

Compass.AI Budget questions got a false answer

"Adventures under 15000 rupees" got "Trail to Tides does not list prices". Budgets are now answered from the site's own "from" prices: "17 adventures start under ₹15,000… Kareri Lake from ₹6,195, Beas Kund from ₹7,875, Bhrigu Lake from ₹7,875". Also handles "below 10k", place and activity ("trek in Uttarakhand below 10k") and budgets nothing fits.

src/app/api/chat/route.ts

Compass.AI "Something easier" recommended a harder motorbike trip

After Pin Parvati Pass (Extreme), "too difficult, something easier nearby?" returned the Zanskar motorcycle ride (Hard, not a trek, 200+ km away). "Easier / harder than X" is now answered from the catalogue: the same activity, rated easier or harder, nearest first. Pin Parvati → Yulla Kanda, Pin Bhaba Pass, Sar Pass; "harder than Kedarkantha" → Bali Pass, Rupin Pass, Buran Ghati. "Kedarkantha" is now recognised even though the trek's name is "Kedarkantha Summit Trek".

Search One typo or a common abbreviation found nothing

"kedarkanta", "goechla" and "EBC" returned 0 results on Explore. The header search box was stricter still: it matched only the exact phrase, so "himachal trek" found nothing. Both now match word by word, forgive one wrong letter (two in long words) and know EBC, ABC, KGL and VoF. Short words still have to match exactly, so "ali" doesn't match half the catalogue.

src/lib/textMatch.ts (new, shared) · exploreHelpers.ts · SearchModal.tsx

ACE "Strongest" and "Room to grow" on a profile with no differences

A profile of eight 3/5 scores was told its strongest capabilities were Stamina and Power and that Nerve and Focus had room to grow, which was just list order. Ties now show only the axes that really are highest or lowest, and an even profile reads "Even across all eight, 3/5 each". The passport's "Strongest in…" line had the same bug and is fixed too.

MatchmakerClient.tsx · passportData.ts · Passport.tsx · api/passport

Reliability Signed-out visitors sent 4–5 failing requests per Matchmaker run

The profile, consent, medical answers and XP were posted to the server for everyone, so signed-out visitors got 401 errors in the console every time. These saves now check for a signed-in session first; the profile still saves in the browser as before.

src/lib/signedIn.ts (new) · matchmaker.ts · awardXP.ts

Checked and working

  • Crawl: 177 pages and 688 query variants. All return 200 except two intended sign-in redirects (/profile, /matchmaker/group). Every indexable page has a title, description, canonical and share image; there are no duplicate titles or descriptions, and every query variant's canonical points back to its base page. The sitemap lists exactly the 171 indexable pages. Unknown adventures, operators, stories, passports and compare codes return real 404s.
  • Numbers agree: 59 adventures; Earth 51 + 4 + 1 + 2 = 58 plus 1 rafting trip; regions add up to 60 because some routes cross two; 2 operators; Explore, the Map and Compass return the same results for the same filters (e.g. 2 Sikkim treks in each).
  • ACE Matchmaker: quick match run end to end. Questions advance, progress survives a page refresh ("Pick up where you left off, Question 9 of 14"), and health questions can be skipped. 36 Ready + 20 Stretch + 3 Not yet = 59; 24 of 40 points gives Trailblazer, 8 points short of Vanguard (32). The scoring script tested 2,832 profile and adventure pairs: nobody is called Ready while 2 or more points short on any axis.
  • Compass.AI: 10 product scenarios run against the live AI: no made-up adventures and no invented prices in any of them.
  • Explore: filters, sorting and the no-results state ("Nothing on Trail to Tides matches…" with ways forward).
  • Map: loads, clusters by difficulty, and filters match the catalogue.
  • Phones and tablets: 23 main pages at 375 px and 768 px. None scrolls sideways.
  • Code and dependencies: lint clean, 61 tests pass, production build clean, 0 known vulnerabilities in production dependencies, no stray debug logging or TODOs. Difficulty is shown from one source (ACE) everywhere.

Low priority

  • The Trek The Himalayas operator page embeds all 1,479 upcoming start dates: 283 kB raw, about 40 kB once compressed. It could load the calendar data on demand.
  • The home page HTML is 592 kB raw, mostly inline SVG and page data. The hero headline is drawn on a canvas, which slows the main paint on phones (a known design trade-off).
  • npm outdated shows major versions available for Next 16, framer-motion 14 and lucide 1.x. None has a security fix, so upgrade when there's time to retest.
