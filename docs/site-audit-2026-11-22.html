P0 — Critical

P0SEC-01Any signed-in user can probably make themselves an adminSuspected, high confidence
Where
supabase/setup.sql:51 policy "Users update own profile"; src/lib/authz.ts requireAdmin()
What
The update policy on profiles is USING (auth.uid() = id) with no WITH CHECK, no column grant and no trigger. The role column accepts 'admin'. The anon key is public by design, so a user can send one REST call with their own session token: PATCH /rest/v1/profiles?id=eq.<me> {"role":"admin"}. requireAdmin() trusts that column.
Evidence
No REVOKE UPDATE or role guard anywhere in supabase/ (the match-group tables do have column grants, so the pattern is known). I could not read live policies over the API, and I didn't create a test account to try it.
Impact
Full admin: read every profile and email, read contact messages, delete or ban users, approve operators, delete reviews and stories.
Fix
Run in the Supabase SQL editor: REVOKE UPDATE ON public.profiles FROM authenticated, anon; GRANT UPDATE (full_name, phone, avatar_url, username, updated_at) ON public.profiles TO authenticated; Then add it as a migration. To confirm first: select policyname, cmd, qual, with_check from pg_policies where tablename='profiles'; plus select privilege_type, column_name from information_schema.column_privileges where table_name='profiles' and grantee='authenticated';

supabase/migrations/20260629000000_create_stories.sql:47; src/lib/stories.ts:125

"Authors can update own stories" has no column limit, and the public site shows any row with status = 'published'. A submitter can change their pending story to published, or rewrite it after approval, including hero_image pointing at any URL.

P1SEC-03Operator sign-up has no rate limit or input checksConfirmed in code
Where
src/app/auth/operator-actions.ts:117 signUpOperator
What
A public server action. Each call creates an account and sends a verification email from your domain through Resend. Traveller sign-up is limited to 5 per 15 minutes; operator sign-up has no limit. Email, phone, company name and website aren't validated.
Impact
Anyone can loop it to email-bomb arbitrary addresses, burn the Resend quota and damage trailtotides.com's sender reputation, which also delays your real verification emails.

Reuse the signUp limiter (per IP), plus a zod schema with length limits.

F. Architecture & security

Stack

  • Next.js 15.5 App Router, React 19, Tailwind 4, on Vercel
  • Supabase: auth (email + Google), Postgres with row-level security, Storage
  • OpenAI for Compass, with data-only answers first and the model as fallback
  • Resend for email; Vercel Analytics
  • Catalogue lives in code (data.ts, 208 KB) plus generated JSON

Structural risks

  • Several stores are JSON files in Storage (operator profiles and listings, XP, wishlists, reactions). Every read lists and downloads files, writes can overwrite each other, and none of it is protected by row-level security. Fine for 5 users, not for 5,000 (PERF-03).
  • Roles live in three places: profiles.role, user_metadata.role, and the operator JSON. Pick one, ideally app_metadata, which users can't edit.
  • Large client files (Matchmaker 91 KB, Group 75 KB, MapDemo 68 KB source) will slow every future change.
